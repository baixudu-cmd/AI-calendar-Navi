# Navi 产品手册

## 一句话介绍

Navi 是一个自用优先的微信 AI 日程助手。你可以在微信里用自然语言告诉它要安排什么、查询什么、修改什么，Navi 会把可执行的日程写入飞书日历，也可以把还没确定时间的事情先放进待推进收件箱。

当前版本的重点不是做一个全能助理，而是把个人日程、待推进事项、排程推荐、早晚报和提醒这几条高频链路做稳。

## 适合处理什么

Navi 适合处理这些场景：

- 把一句话变成日历日程。
- 一次创建多个明确日程。
- 查询某天或一段时间的安排。
- 修改最近创建、查询或工作台里展示过的日程。
- 删除单个或一组明确日程，但删除前会先确认。
- 生成今天工作台、早报、晚报。
- 记录还没确定时间的待推进事项。
- 给待推进事项推荐可安排时间。
- 在推荐后继续要求换时间段、换日期或多给几个候选。
- 识别用户主动发来的日程截图，并在信息完整时转成日程。
- 给已创建日程登记微信提醒。

## 基本使用方式

### 1. 创建单个日程

你可以直接说：

```text
明天下午三点和小李讨论旅行计划
```

Navi 会理解标题、日期和时间，然后写入日历。写入成功后才会回复已创建。

也可以说得更口语：

```text
今天 10 点提醒我看聊天记录
```

如果标题、日期和开始时间都已经足够明确，Navi 会直接创建，不会再追问“是什么类型”这类无关问题。

如果缺少关键时间，Navi 会只问最必要的问题：

```text
明天和小李讨论旅行计划
```

可能回复：

```text
这个日程几点开始？
```

你再补一句：

```text
下午三点
```

Navi 会接上刚才的草稿继续创建。

### 2. 一次创建多个日程

你可以把多个安排放在一句话里：

```text
明天上午 9 点去牙医，下午 2 点取快递，晚上 7 点健身
```

Navi 会按多日程创建处理。当前批量创建一般适合 2 到 5 个明确日程。

如果其中一个时间已经有安排，Navi 不会直接写入这一批日程，会先告诉你冲突在哪里，并把本次请求里其他尚未写入的事项一起列出来，避免后面的安排被漏掉。

### 3. 查询日程

你可以问：

```text
查一下今天日程
```

```text
明天有什么安排？
```

```text
这周五下午有哪些会？
```

Navi 会只读日历并按时间顺序展示结果。查询不会写入日历。

### 4. 修改日程

如果刚创建或刚查询过日程，可以直接接着说：

```text
刚才那个改到 4 点
```

或者在工作台 / 早晚报后说：

```text
第二个改到明天下午三点
```

Navi 会尽量基于当前上下文定位目标。目标不清楚时，不会猜着改，会要求你补充。

### 5. 删除日程

可以说：

```text
把明天下午讨论旅行计划那个安排删掉
```

或：

```text
把周二所有日程删掉
```

删除不会直接执行。Navi 会先锁定待删除对象并让你确认。你可以回复：

```text
确认
```

或：

```text
取消
```

只有确认后才会真正删除日历事件。

## 今日工作台

今日工作台会把日程和待推进事项放在一起，方便继续处理。

你可以说：

```text
打开今天工作台
```

或：

```text
今天有什么要处理的？
```

工作台通常会展示：

- 今天的日程。
- 当前还没处理完的上下文，例如待确认推荐或待补时间。
- 待推进事项。
- 每一项的编号。

看到编号后，可以继续直接操作：

```text
第一个完成了
```

```text
前两个不用再记了
```

```text
第二个明天下午提醒我
```

```text
第二个先别提醒了
```

这些操作只会修改待推进收件箱，不会直接写飞书日历。

如果不确定系统当前还挂着什么，可以直接问：

```text
你现在记着我什么？
```

Navi 会只读汇总当前待补时间、待确认推荐、待确认删除和待推进事项，不会写日历。

如果只是想放弃当前挂起的对话，可以说：

```text
算了，先不管了
```

Navi 会清空当前待补时间、待确认推荐、待确认删除、冲突确认或图片草稿。这个动作不会删除日历，也不会清掉待推进收件箱。

## 待推进事项

待推进事项适合放还没有明确时间、但之后要处理的事情。

你可以说：

```text
记一下，下周要整理旅行清单
```

```text
先记着，找时间看一下体检报告
```

```text
把办签证这件事先放待推进
```

Navi 会把它放进 Seed Lite 待推进收件箱。

如果你希望直接安排，可以说：

```text
把第一个安排一下
```

```text
把前两个都安排一下
```

```text
把第一个和第三个找时间安排
```

Navi 会根据当前日历给出候选时间。确认前不会写入日历。

## 排程推荐

当事情还没有具体时间时，可以让 Navi 先推荐时间。

```text
帮我明天下午找一小时整理资料
```

```text
这周找个时间处理报销
```

```text
把待推进里的第二个安排到明天
```

Navi 会读取当前日历，给出候选位，并保存为待确认推荐。推荐回复会显示候选数量，并明确提示确认前不会写入日历。

你可以继续调整：

```text
换下午
```

```text
晚一点再推荐
```

```text
明天吧
```

```text
多给我几个候选
```

当前支持 1 到 5 个候选时间。你确认某个候选后，Navi 才会写入日历。

示例：

```text
选第二个
```

```text
就第一个
```

```text
取消推荐
```

## 混合请求

你可以在一句话里同时放明确日程和未定事项：

```text
明天上午 10 点去体检，下午找时间整理旅行清单
```

Navi 会先处理上午明确日程，再为下午未定事项推荐时间。

如果明确日程有冲突，Navi 也会继续保留下午事项的排程推荐，不会因为上午冲突把后半句丢掉。即使模型把两件事都当成批量创建，冲突回复也会列出本次尚未写入的其他事项。

## 早报、晚报和提醒

### 早报

早报适合看今天安排和待推进事项：

```text
早报
```

或由主动任务在固定时间发送。

如果当前还有待确认推荐、待补时间或冲突确认，早报也会把这些待处理上下文带出来，方便直接回复处理。

### 晚报

晚报适合看明天安排：

```text
晚报
```

如果明天没有日程，Navi 会明确告诉你明天没有安排。

晚报同样会展示待处理上下文，避免排程推荐或追问状态在第二天前被遗忘。

### 微信提醒

日程创建成功后，Navi 可以登记微信提醒。当前默认提醒策略收敛为提前 40 分钟一次。用户明确说“不用提醒”或指定提醒方式时，以本次指令为准。

## 图片和截图

你可以主动发预约截图、活动截图或日程卡片。

Navi 会尝试从图片中识别标题、日期、时间等信息。如果信息完整，会走正常日程创建链路。如果识别不清楚，会失败关闭或要求补充，不会把不完整图片强行写进日历。

当前边界：

- 不后台截图。
- 不长期保存图片。
- 不读取桌面或浏览器内容。
- 只处理用户主动发给 Navi 的图片。

## 记忆整理

Navi 有本地记忆整理能力，用来归纳日程助手自身交互、执行结果和待推进事项。

当前记忆只做本地、可审计、只读归纳：

- 不后台读屏。
- 不后台截图。
- 不读取浏览器。
- 不把整理结果直接变成自动写日历行为。

## 可靠性规则

Navi 当前遵循几条硬规则：

- 模型只负责理解和选择工具。
- 创建、修改、删除是否成功，只看日历 API 的真实结果。
- 没有工具成功结果，就不能回复“已创建”“已修改”“已删除”。
- 删除必须先确认。
- 推荐排程确认前不写日历。
- 待推进提醒时间只记录在收件箱里，不等于日历提醒。
- 旧追问或旧推荐不会自动污染新事项，只有明确续接当前推荐时才复用旧状态。
- 标题和类型默认由模型根据原文整理，不要求用户补“日程类型”或“事项类型”。

## 当前不适合期待什么

这些能力当前不作为默认目标：

- 多用户系统。
- Web 后台管理。
- 自动读取微信群。
- 后台截图或后台读屏。
- 自动替你和外部人员约时间。
- 大规模条件触发器。
- 未确认就自动排满一整天。
- 把所有历史聊天都当长期记忆。
