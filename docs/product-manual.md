# Navi 产品手册

Navi 是一个可自托管的 AI 日程助手。它接收自然语言、语音转写文本和图片 OCR 文本，理解后通过受控工具完成日程创建、查询、修改、删除、提醒和排程推荐。

## 核心能力

- 创建单个或多个明确日程。
- 查询指定日期或时间段的日程。
- 修改刚展示、刚创建或结构化查询到的日程。
- 删除日程前先确认，避免误删。
- 把未确定时间的事项放入待推进收件箱。
- 基于日历空档生成排程候选。
- 生成早报、晚报、状态总览和设置总结。
- 支持默认提醒和指定时间提醒。
- 支持图片或截图 OCR 文本进入同一套日程理解流程。
- 用本地记忆整理辅助后续排程推荐。

## 使用示例

### 创建日程

```text
明天下午三点和小李讨论旅行计划
```

如果标题、日期和开始时间都足够明确，Navi 会直接创建日程。写入成功后才会回复已创建。

如果缺少关键时间，Navi 只问必要问题：

```text
明天和小李讨论旅行计划
```

可能回复：

```text
这个日程几点开始？
```

补充时间后，Navi 会接上刚才的草稿继续处理。

### 批量创建

```text
明天上午 9 点去牙医，下午 2 点取快递，晚上 7 点健身
```

批量创建适合 2 到 5 个明确日程。如果其中一项发生冲突，Navi 会说明冲突，并列出本次尚未写入的其他事项。

### 查询日程

```text
查一下今天日程
```

```text
明天有什么安排？
```

查询只读日历，不会写入或修改任何日程。

### 修改日程

```text
刚才那个改到 4 点
```

```text
第二个改到明天下午三点
```

Navi 会优先使用刚展示过的编号或结构化条件定位目标。目标不唯一时，会要求选择具体对象。

### 删除日程

```text
把明天下午讨论旅行计划那个安排删掉
```

Navi 会先列出待删除对象并等待确认。只有确认后才会真正删除。

## 待推进收件箱

待推进收件箱用于保存还没有明确时间、但之后需要处理的事项。

```text
记一下，下周要整理旅行清单
```

```text
先记着，找时间看一下体检报告
```

常用操作：

| 操作 | 示例 |
| --- | --- |
| 查看 | `现在有哪些待处理事项？` |
| 完成 | `第一个完成了` |
| 取消 | `前两个不用再记了` |
| 设置提醒 | `第二个明天下午提醒我` |
| 关闭提醒 | `第二个先别提醒了` |
| 安排时间 | `把第一个安排一下` |

待推进提醒只记录在收件箱里，不等同于日历事件。用户明确要求转成日程或确认推荐后，才会写入日历。

## 排程推荐

当事项没有具体时间时，可以让 Navi 推荐空档：

```text
帮我明天下午找一小时整理资料
```

```text
这周找个时间处理报销
```

Navi 会读取当前日历并给出候选时间。确认前不会写入日历。

推荐后可以继续调整：

```text
换下午
```

```text
多给我几个候选
```

```text
选第二个
```

## 早报、晚报和提醒

- 早报：展示当天日程、待推进事项和未处理上下文。
- 晚报：展示次日安排和仍需处理的事项。
- 提醒：日程创建成功后可登记提醒；默认提醒时间由 `config/settings.local.json` 控制。

如果存在待确认推荐、待补时间或冲突确认，早晚报会一并展示，方便继续处理。

## 图片和截图

Navi 可以处理用户主动发送的预约截图、活动截图或日程卡片。图片会先经过 OCR，再进入同一套日程理解流程。

边界：

- 不后台截图。
- 不长期保存图片。
- 不读取桌面或浏览器内容。
- 不把信息不完整的图片强行写入日历。

## 可靠性规则

- 模型负责理解和选择工具。
- 工具负责创建、修改、删除和提醒登记。
- 没有工具成功结果，就不能回复已创建、已修改或已删除。
- 删除、冲突创建和排程推荐都有确认门禁。
- 本地记忆可以影响推荐，但不能直接写入或移动日程。
- 标题和类型由模型整理，不要求用户补充无关分类。

## 配置入口

- `.env`：密钥、外部服务 ID 和 live 写入开关。
- `config/settings.local.json`：默认提醒时间、早晚报开关、排程候选数量、状态文件路径等非密钥设置。

公开仓库只提供 `.env.example` 和 `config/settings.example.json`。本地配置不要提交到 Git。
